一、中断

轮询是 CPU 主动问：

中断是设备主动通知 CPU：

中断的核心价值在于不需要 CPU 一直轮询，并且在此期间 CPU 可以做别的事情。中断适合按键、网卡、摄像头、DMA、VPU、NPU 这类异步事件。

三、上半部与下半部

一个真实中断往往包含两类事情：

所以内核把中断处理拆成上半部和下半部：

部分 上下文 做什么
上半部 hardirq 中断上下文 最快速度确认事件、记数、清中断、调度下半部
下半部 softirq / 进程上下文 耗时处理、拷贝数据、投递队列、唤醒用户态

下半部常见机制：

机制 上下文 能否睡眠 适合
softirq 中断相关上下文 不能 网络等高吞吐场景
tasklet softirq 不能 旧的轻量延后处理
workqueue 进程上下文 能 需要睡眠、加锁、耗时的处理
threaded IRQ 内核线程 能 处理逻辑天然属于该中断

可以按下面的判断表选机制：

需求 推荐机制
只是为了不丢事件，做最少处理 hardirq 上半部
极短、不能睡眠、对延迟敏感 tasklet
需要睡眠、拿 mutex、做耗时事情 workqueue
处理逻辑天然属于这个中断，希望内核帮你管理线程 threaded IRQ
只是想等一个事件发生 waitqueue / completion
用户态同时等多个设备 poll / epoll + waitqueue
