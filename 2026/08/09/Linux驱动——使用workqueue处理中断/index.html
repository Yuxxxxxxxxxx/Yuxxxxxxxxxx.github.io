Linux驱动——使用workqueue处理中断

一、workqueue 与 tasklet 的区别

前面已经讲过中断和 tasklet 了，本文将介绍使用 workqueue 来处理中断。首先来看下它和 tasklet 有什么区别。

对比项 tasklet workqueue
上下文 softirq 进程上下文
能否睡眠 不能 能
能否拿 mutex 不能 能
执行者 softirq 机制 kworker 内核线程
延迟 通常更低 受调度影响
适合 极短、原子性处理 耗时、可能睡眠
新代码推荐 少用 优先

tasklet 运行在软中断上下文中，操作必须是原子的；而 workqueue 运行在内核进程上下文中，操作不必是原子的。因此 workqueue 具有更大的灵活性。特别是，workqueue 可以休眠。

选择规则：

现代内核里，很多过去用 tasklet 的场景会改写为 threaded IRQ 或 workqueue。除非你维护旧驱动或明确需要 softirq 级延迟，否则不应该优先选择 tasklet。

二、workqueue 的使用

2.1 workqueue

创建 workqueue：

如果因为某些原因，如需要执行的是个阻塞性质的任务而不愿或不能使用内核提供的共享 workqueue，这时需要自己创建 workqueue。

创建 workqueue 时，有 2 个选择，可选择系统范围内的 ST，也可选择每 CPU 一个内核线程的 MT。

  • single threaded (ST):：工作者线程的表现形式之一，在系统范围内，只有一个工作者线程为workqueue服务
  • multi threaded (MT)：工作者线程的表现形式之一，在多 CPU 系统上每个 CPU 上都有一个工作者线程为 workqueue 服务

相对于 create_singlethread_workqueue，create_workqueue 同样会分配一个 wq 的 workqueue。

不同之处在于，对于多 CPU 系统而言，create_workqueue对每一个 active 的 CPU，都会为之创建一个 per-CPU 的 cwq 结构，对应每一个 cwq，都会生成一个新的 worker_thread。
