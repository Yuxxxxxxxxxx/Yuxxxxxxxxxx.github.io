CUDA tile

一、什么是 Tile？

在 CUDA 编程中，Tile（瓦片 / 分块） 指的是把一个大问题切成许多大小固定、能装载进快速存储（共享内存 / 寄存器）的小块，让线程块（block）或线程（thread）以这些小块为单位循环处理。

简而言之，Tile 就是"数据搬运"与"数据计算"之间的桥梁——它让同一块数据被多次复用，从而把全局内存的带宽瓶颈转化为片上高速存储的吞吐问题。

以矩阵乘法 C = A × B 为例，朴素实现中每个 C 元素都要重新读一遍 A 的一行和 B 的一列，重复读取量是 O(N) 级的。而 tiling 让每个线程块只从全局内存加载一次数据，然后在共享内存里反复使用，全局内存访问量从 O(N³) 降到 O(N²)。

场景 Tile 的对象 收益来源
矩阵乘法 A 的行块、B 的列块 输入复用降到 O(N²)

四、注意

Tile 不是越大越好，需要平衡以下几个因素：

1. Tile 大小 vs 占用率（Occupancy） 共享内存是有限的（如 SM 上 48KB~164KB）。tile 越大，单个 block 占用越多，能同时驻留的 block 越少。必须在"数据复用率"和"延迟掩盖能力"之间找平衡点。

2. Bank Conflict 共享内存被划分成 32 个 bank。若同一 warp 的多个线程访问同一 bank 的不同地址，会串行化。典型对策：

  • Padding（如上例 [TILE][TILE+1]）
  • 交换索引布局
  • 使用 swizzle（CUTLASS 常用的 XOR 打散）

3. 同步开销 每个 tile 迭代至少两次 __syncthreads()。tile 太小 → 同步太频繁；tile 太大 → 并行度不足。

4. 边界检查 当矩阵维度不是 tile 尺寸的整数倍时，加载阶段需要判断越界并用 0 填充（对加法/乘法是恒等元）。
